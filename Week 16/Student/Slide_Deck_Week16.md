### Slide 3: ปูพื้นฐานความเข้าใจด้วยการเปรียบเทียบ (Theory & Analogy)
* **1. การแชร์ Header & Footer (Shared Components):**
  * *เปรียบเทียบ:* เหมือน "เสาไฟส่องสว่างมาตรฐานและป้ายบอกทางของหมู่บ้านจัดสรร"
  * เราไม่หล่อเสาไฟใหม่หน้าบ้านทุกหลัง แต่เราทำแบบพิมพ์เขียวอันเดียว (`components.js`) แล้วสั่งให้ทุกบ้านติดตั้ง (`<site-header>`) ถ้าวันหน้าต้องการเปลี่ยนหลอดไฟ เราเปลี่ยนที่ต้นฉบับเพียงจุดเดียว ทุกบ้านสว่างพร้อมกันทันที
* **2. การทดสอบคุณภาพ (Quality Assurance - QA):**
  * *เปรียบเทียบ:* เหมือน "ด่านตรวจรถยนต์ก่อนส่งมอบให้ลูกค้า"
  * ช่างต้องทดสอบเปิดไฟเลี้ยว แอร์ เบรก และวิ่งบนถนนขรุขระ (จอมือถือ) ว่ามีจุดไหนติดขัดหรือไม่ ไม่ใช่รอให้ลูกค้าซื้อไปขับแล้วเครื่องดับกลางทาง
* **3. GitHub & GitHub Pages:**
  * *เปรียบเทียบ:*
    * **Local Computer (เครื่องเรา):** เหมือน "สมุดวาดเขียนในห้องนอน" มีเราเห็นคนเดียว
    * **GitHub (Cloud Repository):** เหมือน "ตู้เซฟเก็บผลงานออนไลน์" ฝากไฟล์ปลอดภัย ไม่หายแม้คอมพัง
    * **GitHub Pages (Web Hosting):** เหมือน "ป้ายบิลบอร์ดแสดงผลงานหน้าโรงเรียน" นำภาพในสมุดวาดเขียนมาจัดแสดงให้คนทั่วโลกเดินมาดูได้ฟรี 24 ชั่วโมง

### Slide 4: สรุปคำสั่งและไวยากรณ์สำคัญ (Syntax & Cheat Sheet)
* **1. การเรียกใช้ Shared Components ใน HTML:**
  ```html
  <!-- วางใต้แท็ก <body> -->
  <site-header active="index.html"></site-header>

  <!-- เนื้อหาของหน้า... -->

  <!-- วางก่อนปิดแท็ก </body> -->
  <site-footer></site-footer>
  <script src="components.js"></script>
  ```
* **2. CSS ป้องกันภาพล้นขอบจอเวลาเปิดบนมือถือ (Responsive Image):**
  ```css
  img {
    max-width: 100%;
    height: auto;   /* ป้องกันภาพตกขอบจอ และรักษาสัดส่วน */
  }
  ```
* **3. ตรวจสอบสถานะลิงก์ในแต่ละหน้า (Navigation Link Checklist):**
  * `index.html` ➡️ `active="index.html"`
  * `course.html` ➡️ `active="course.html"`
  * `instructors.html` ➡️ `active="instructors.html"`
  * `contact.html` ➡️ `active="contact.html"`

### Slide 9: จุดระวังและเทคนิคป้องกันบั๊ก (Pro-Tips & Bug Prevention)
* **⚠️ บั๊กที่ 1: หน้าแรกเปิดไม่ติด (404 Not Found บน GitHub Pages):**
  * *สาเหตุ:* ตั้งชื่อไฟล์หน้าแรกเป็น `Index.html` (ตัวใหญ่) หรือ `home.html`
  * *วิธีแก้:* หน้าแรกของเว็บไซต์ต้องสะกดด้วย **ตัวพิมพ์เล็กล้วน** คือ `index.html` เท่านั้น!
* **⚠️ บั๊กที่ 2: รูปภาพแตกหรือไม่แสดงผลบนเซิร์ฟเวอร์จริง:**
  * *สาเหตุ:* สะกดชื่อไฟล์ไม่ตรงกับตัวพิมพ์เล็ก-ใหญ่ หรือเรียกรูปจากไดรฟ์ตัวเองเช่น `C:/Users/...`
  * *วิธีแก้:* ใช้ลิงก์ CDN ออนไลน์ หรือ Relative Path เช่น `image/filename.png`
* **⚠️ บั๊กที่ 3: แก้โค้ดแล้ว แต่บนมือถือหน้าเว็บยังไม่ยอมเปลี่ยน:**
  * *สาเหตุ:* เบราว์เซอร์จำหน้าเก่า (Browser Cache)
  * *วิธีแก้:* กด Refresh แบบล้างแคช (`Ctrl + F5` หรือ `Cmd + Shift + R`) หรือเปิดในแท็บไม่ระบุตัวตน (Incognito)

### Slide 11: คำถามชวนคิดท้ายคาบ (Reflection Quiz)
1. **คำถามข้อที่ 1:** ทำไมการแชร์ Header และ Footer ผ่านไฟล์ `components.js` จึงดีกว่าการคัดลอกโค้ด Navbar ไปวางไว้ในทุกๆ ไฟล์ HTML?
   * *แนวคำตอบ:* ทำให้เป็น Single Source of Truth แก้ไขเมนูหรือลิงก์เพียงจุดเดียวมีผลอัปเดตทุกหน้าทันที ประหยัดเวลาและลดความผิดพลาด (หลักการ DRY)
2. **คำถามข้อที่ 2:** การทดสอบเว็บด้วยฟังก์ชัน "Device Toggle Toolbar" มีความสำคัญอย่างไรก่อนส่งมอบงานจริง?
   * *แนวคำตอบ:* ช่วยจำลองหน้าจอมือถือและแท็บเล็ตขนาดต่างๆ เพื่อให้มั่นใจว่าปุ่มกดไม่ตกขอบ ภาพไม่บวม และผู้ใช้สมาร์ตโฟนได้รับประสบการณ์การใช้งานที่ดีเยี่ยม
3. **คำถามข้อที่ 3:** เมื่อเปิดใช้งาน GitHub Pages แล้ว โค้ด HTML ของเราถูกนำไปเก็บและประมวลผลไว้ที่ใด?
   * *แนวคำตอบ:* อยู่บน Cloud Server ของ GitHub ซึ่งพร้อมให้บริการผู้ใช้งานทั่วโลกผ่าน URL ตลอด 24 ชั่วโมงโดยไม่ต้องเปิดเครื่องคอมพิวเตอร์ของเราทิ้งไว้
